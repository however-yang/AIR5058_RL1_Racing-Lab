# AIR5058 · 作业 1 · 用 Q-learning 跑完一圈

## 任务

使用第 6 讲的表格 Q-learning，在 MuJoCo 上海赛道训练一辆赛车。用同一份 Q 表在干地和低抓地两种路面稳定跑完一圈，再尝试比固定速度中线基线更快。弯前何时减速、出弯何时加速、何时偏离中线，都由你设计的 Q 表决定。

## 框架与接口

- 赛道信息由车身坐标系下前方五个中心线采样点和赛道宽度表示。中心线文件只含几何，赛道没有预设赛车线、建议速度、刹车点或弯心动作。
- 策略入口是 `act(observation) -> (offset_m, target_speed_mps)`。横向目标以米为单位，正为左，范围为赛道半宽以内（±1.05 m）。目标速度范围为 0–5.00 m/s。双方共用的几何执行器将目标转成车辆控制请求。
- 两个动作分量都由学生离散化。可以在连续控制步保持同一个动作，仿真控制步仍为 0.05 秒。状态分箱、动作集合、奖励、探索率、学习率和训练预算由学生自己设计。
- 固定中线基线每步请求零横偏和 3.40 m/s。该数值只用于统一对照。学生策略可以从这些观测量自行构造速度差、判断前方是否需要减速。
- 在 `student_policy.py` 实现状态、动作、奖励、训练和加载钩子。环境支持 `Lab(reward_fn=reward)`，训练奖励回调接收 [RewardSignals](racing/reward.py)。评测只调用冻结策略的 `act(observation)`，训练时的奖励回调由学生自行配置。

| 观测索引 | 物理含义 |
| --- | --- |
| 0–9 | 前方 0.6、1.3、2.2、3.5、5.0 m 的五个中心线点，每点是车身坐标系中的前向与左向分量，均除以 5 m |
| 10 | 相对中心线的横向偏差，除以赛道半宽 |
| 11–12 | 航向误差的正弦和余弦 |
| 13–14 | 车身前向与横向速度，除以 5 m/s |
| 15 | 横摆角速度，除以 5 rad/s |
| 16–17 | 两个前轮实测转角，除以最大轮角 |
| 18–19 | 实际转向对应的虚拟转角和当前速度设定值，分别除以最大转向角和 5 m/s |

## 比赛规则

1. 所有正式成绩由助教从统一的随机起点重跑。沿正向依次通过全部 8 个检查点，且在 48 秒内通过终点，记为完赛。
2. 车辆占地范围越出赛道即判失败。翻车、持续超速、超时、无效动作或物理错误也记为未完赛。环境在仿真步内检查出界，绕开检查点不能刷新圈速。轮胎接触、抓地、转向响应与限速由统一的 MuJoCo 环境处理。
3. 训练可使用上海两种公开路面。`Lab(surface="dry")` 使用摩擦系数 0.90，`Lab(surface="low-grip")` 使用 0.82。正式评测在两种路面加载同一份冻结 Q 表，关闭学习与随机探索。策略入口只接收车辆观测，环境不会传入路面标签或摩擦系数。
4. 策略只用公开观测、状态分箱和学出的 Q 值决策。禁止根据赛道编号、绝对里程、检查点编号或评测种子查动作，禁止写死逐弯走线或制动点。禁止修改车辆、摩擦、地图、仿真时钟、判罚、评测器或访问隐藏评测状态。可以由公开几何与车辆观测推导曲率、横漂或制动余量，推导结果用于 Q 表状态或训练奖励。

## 评测与评分（70 / 30）

上海干地和低抓地都纳入正式评分。两种路面使用同一组 20 个助教起点，基线和提交策略按起点配对。**两种路面必须各有至少 19/20 圈完赛。** 任一路面低于门槛，总分记 0。单次未完赛的起点在两个评分项都记 0，并计入该路面的 20 圈平均。每种路面各按下表计算 100 分，再将两种路面的成绩各取 50% 得到总分。

| 评分项 | 权重 | 算法 |
| --- | ---: | --- |
| 整圈用时 | 70 分 | 对每个完赛起点，计算相对同起点固定中线基线的节省比例。与基线持平或更慢计 0，节省 15% 计满档，中间线性换算。所有起点取平均后乘 70。15% 为固定满档线，整班统一。 |
| 弯中有效抓地利用 | 30 分 | 对每个完赛起点，在预先定义的弯道距离采样点上计算有效抓地利用率。每圈按弯道距离平均，再对所有起点取平均并乘 30。 |

### 弯中抓地怎么算

1. **先固定评分位置。** 用官方中心线切线计算曲率，采样间距约 0.10 m，曲率绝对值达到 0.14 m⁻¹ 才纳入。每个采样点只记首次通过的值，按距离平均，停车、倒车后重跑或在弯里磨时间都不能多攒分。
2. **只计用于过弯的轮胎力。** 将 MuJoCo 解算的各轮胎地面切向力合计，取朝弯内侧的分量，再除以该时刻的可用摩擦力。纵向加速和刹车、朝弯外发力、轮胎间互相抵消的力均不能抬高该值。单个采样点封顶 100%。分母至少取静态整车抓地预算的 75%，避免通过卸载轮胎把比值抬高。
3. **明显横滑降分。** 用实际车速方向与车头方向之间的夹角衡量车身侧滑。8° 以内给足当前样本的利用率，8° 到 16° 线性衰减，16° 起记 0。样本仍留在分母里。整圈出界或其他原因未完赛，整圈抓地分记 0。

### 如何执行正式评测

- 同一份提交在全部种子上只跑统一次数，起点表由助教保存。评测用提交时冻结的表、确定性动作和官方程序重新运行。提交报告、截图、视频和自报圈速用于说明，正式分数取重跑结果。
- 助教使用自己的干净副本和预先核验全完赛的基线起点。基线异常时作废该批，排查后用同一批起点重跑全班。所有阈值和物理参数在发布前统一冻结。
- 评测执行学生代码时，正式运行应把学生策略与仿真和评分置于隔离进程，通过数值观测和动作通信。策略进程只应能读取本次提交文件，禁止联网、读取评测文件、访问或修改仿真与计时。随包 `evaluate.py` 用于公开起点自测，和学生策略在同一进程。
- 分段、直道最高车速和抓地峰值可用于报告和核对异常。单个峰值、最快单圈、外内外走线都不另计分。

## 运行

在本目录启动。Conda 环境只含 CPU 训练所需依赖。

```bash
conda env create -f environment.yml
conda activate air5058-racing-student
python evaluate.py --count 2
python student_policy.py --output submission.npz --seed 42
python evaluate.py --checkpoint submission.npz --count 20 --output results/shanghai.json
```

训练和提交评测前需要先实现 `student_policy.py` 中的训练函数和 `load_policy`，然后自行训练保存提交表。`submission.npz` 是示例文件名。建议保存数值型 Q 表及其分箱、动作配置，加载时使用 `allow_pickle=False`。命令默认使用公开调试起点，正式测试由助教另行指定。结果 JSON 保留每个起点的完赛状态、圈速、分段和物理观测。


### 车速与抓地图

评测默认跑两种路面。需要单独调试时，可以传 `--surface dry` 或 `--surface low-grip`。提供 `--plot` 时，每种路面画一张对照图。未提供 `--checkpoint` 时只画基线。默认画这一批的第一个起点，`--plot-seed` 可以选本批中的其他种子。

```bash
python evaluate.py --checkpoint submission.npz --count 20 --plot results/performance.png --output results/shanghai.json
```

上述命令输出 `performance-dry.png` 和 `performance-low-grip.png`。两种路面的分项及总分都记录在 `shanghai.json`。

- 上图是实际地速，浅绿色标出中心线几何识别的直道，虚线为配置上限 5.00 m/s。绿色参考线为上限的 95%（4.75 m/s）。配置上限是控制限制，车辆在有限直道上实际可达的速度取决于动力和阻力。
- 下图是**与计分相同的弯中有效抓地**。淡线保留实际样本，实线为约 0.5 m 的局部距离均值，便于区分持续利用和短暂尖峰。点线显示侧滑扣分前的向内抓地。直道、过渡区及未跑到的路段不会填零冒充实测。
- 配合 `--output`，每圈 JSON 记录直道峰值速度、已通过直道中达到配置上限 95% 的距离占比、已通过弯段中有效抓地达到 90% 的距离占比，以及已覆盖样本数。图中起点还会保留逐点数据。未完赛曲线仅用于诊断，两个参考阈值不另外计分。
